# Статистика сайту в Umami — куди дивитись

Сайт шле статистику в **Umami Cloud**: https://cloud.umami.is (вхід — своїм акаунтом).
Рахується лише справжній сайт `football-party-games.onrender.com` — локальний запуск, автотести й `ui-check` туди не потрапляють.
Cookies немає, особистих даних немає: Umami бачить лише «анонімного відвідувача», країну, браузер, пристрій і сторінки.

> Назви кнопок в Umami інколи міняються з оновленнями. Якщо чогось не знайшов за назвою — шукай за змістом
> (вкладки над графіком, фільтр із лійкою, перемикач періоду вгорі праворуч).

---

## 1. Як відкрити сайт у Umami

1. Зайди на https://cloud.umami.is.
2. Угорі — **Websites** (список сайтів). Клікни на **football-party-games**.
3. Відкриється сторінка сайту. Угорі праворуч — **період** (Today / Last 24 hours / Last 7 days / Last 30 days / свій діапазон).
   Усе нижче показується за вибраний період — це перше, що варто перемкнути.

Над графіком — вкладки сайту: **Overview**, **Events**, **Sessions**, **Realtime**, **Compare**, **Reports** (може бути ще кілька).

## 2. Швидкі відповіді: «хочу дізнатись…»

| Хочу дізнатись | Куди йти |
|---|---|
| Скільки людей заходило за тиждень | **Overview** → період *Last 7 days* → число **Visitors** |
| Хто на сайті просто зараз | **Realtime** (оновлюється сам). Те саме видно на головній сайту — «Зараз на сайті» |
| Які ігри відкривають найчастіше | **Overview** → прокрутити вниз до таблиці **Pages** (див. розділ 3) |
| У яку гру реально **грають** (починають партію) | **Events** → подія `game_start` → властивість `game` (розділ 4) |
| Скільки партій дограють до кінця | **Events**: порівняти `game_start` і `game_finish` для гри (розділ 5) |
| Де кидають гру посередині | **Events** → `game_leave` → `game` |
| Грають самі чи з друзями | **Events** → `game_start` → властивість `mode` (`solo` / `room`) |
| З телефона чи з комп'ютера | Для всіх відвідувачів — **Overview** → таблиця **Devices**. Для ігор — **Events** → `game_start` → `device` |
| Скільки людей у кімнатах | **Events** → `game_start` → `players` |
| У якій грі найчастіше беруть підказки / здаються | **Events** → `hint` або `give_up` → `game` |
| Скільки відгуків і яких | **Events** → `feedback` → `kind` (`like` / `idea` / `bug`), `game`. Самі тексти — у GitHub Issues з міткою `feedback` |
| Звідки приходять (Telegram, Google…) | **Overview** → таблиця **Referrers** |
| З яких країн | **Overview** → таблиця **Countries** (або карта) |
| Як змінилось за тиждень порівняно з попереднім | **Compare** (або в **Overview** перемикач порівняння з попереднім періодом) |
| Скільки часу сидять на сайті | **Overview** → **Visit duration** (середній час візиту) |

## 3. Overview — загальна картина

Зверху — п'ять чисел за період (поруч зі стрілкою — зміна відносно попереднього такого ж періоду):

- **Visitors** — різні люди (точніше — різні браузери/пристрої). Головне число «скільки нас».
- **Visits** — заходи. Одна людина, що зайшла вранці й увечері, — 1 visitor, 2 visits.
- **Views** — переглянуті сторінки.
- **Bounce rate** — частка заходів, де людина відкрила одну сторінку й пішла. У нас це не обов'язково погано:
  хтось відкрив посилання-запрошення в кімнату, пограв і закрив — це теж «bounce».
- **Visit duration** — середній час одного заходу.

Нижче графіка — таблиці (у кожній можна клікнути **View more** / розгорнути):

- **Pages** — які сторінки відкривали. Кожна гра — своя адреса:

  | Адреса | Гра |
  |---|---|
  | `/` | головна (альбом наліпок) |
  | `/changes/` | «Що нового» |
  | `/crossroads/` | Футбольне перехрестя |
  | `/path/` | Шлях футболіста |
  | `/guess/` | Вгадай гравця |
  | `/spy/` | Футбольний шпигун |
  | `/top/` | Топ-10 |
  | `/duel/` | Один на один |
  | `/lineup/` | Склад матчу |
  | `/archive/` | Фотоархів |
  | `/sketch/` | Тактичний ескіз |
  | `/fours/` | Чотири четвірки |
  | `/handshake/` | Правило рукостискань |
  | `/allin/` | All in |
  | `/window/` | Трансферне вікно |

  Відкриття сторінки ≠ гра: людина могла зайти, подивитись правила й піти. Чи справді грали — дивись події (розділ 4).
- **Referrers** — звідки прийшли (сайт чи застосунок, з якого перейшли за посиланням). Порожньо / *Direct* — набрали адресу,
  відкрили із закладок або з месенджера, який не передає джерело.
- **Browsers**, **OS**, **Devices** — браузер, система, тип пристрою (desktop / mobile / tablet).
- **Countries** / **Regions** / **Cities** — звідки люди (за IP, приблизно).
- **Events** — коротка таблиця ігрових подій (детально — у вкладці **Events**).

**Фільтр.** Клікни на будь-який рядок таблиці (наприклад, сторінку `/spy/` або країну *Ukraine*) — уся сторінка
перерахується лише для нього. Або кнопка з лійкою **Filter** вгорі. Прибрати фільтр — хрестик біля нього вгорі.
Приклад: фільтр *Devices = mobile* → таблиця **Pages** покаже, які ігри відкривають з телефона.

## 4. Events — що відбувається в іграх

Окрім переглядів сторінок, сайт сам надсилає **події** — коли в грі щось сталося:

| Подія | Коли надсилається |
|---|---|
| `game_start` | почалась партія (соло або кімната) |
| `game_finish` | партію дограли до підсумку |
| `game_leave` | натиснули «Вийти з гри» посеред партії |
| `hint` | взяли підказку |
| `give_up` | натиснули «Здатися» |
| `feedback` | надіслали відгук кнопкою «💬 Відгук про гру» |

У кожної події є **властивості** (додаткові дані):

| Властивість | Значення |
|---|---|
| `game` | яка гра — та сама назва, що в адресі: `spy`, `top`, `fours`… (таблиця в розділі 3) |
| `mode` | `solo` — сам, `room` — кімната з друзями |
| `players` | скільки гравців у кімнаті в цей момент (у соло — 1) |
| `device` | `pc` — комп'ютер, `phone` — телефон, `tablet` — планшет |
| `kind` | лише у `feedback`: `like` — подобається, `idea` — ідея, `bug` — щось зламалось |

**Як подивитись:**

1. Вкладка **Events**.
2. Угорі — графік усіх подій за період і таблиця подій з кількістю (скільки разів кожна).
3. Нижче — блок **властивостей** (Properties / Event data): обери подію (наприклад, `game_start`), потім властивість
   (`game`) — побачиш таблицю/діаграму «скільки разів яке значення». Це і є «у що грають найбільше».
4. Щоб розрізати ще й за іншою ознакою — додай фільтр (лійка), наприклад *mode = room*, і знову подивись `game`:
   побачиш, у які ігри грають саме компанією.

## 5. Готові рецепти

**Найпопулярніша гра за місяць.** Період *Last 30 days* → **Events** → `game_start` → властивість `game`.
Порівнюй саме `game_start`, а не відвідування сторінок.

**Чи дограють гру.** Для гри (фільтр *game = fours*) порівняй кількість `game_start` і `game_finish`.
Наприклад, 100 стартів і 70 фінішів — 70 % партій доходять до кінця. Багато `game_leave` — гравці кидають гру, варто
подивитись, що там не так (і чи нема відгуків `bug` про неї).

**Гра занадто складна?** Фільтр *game = …* і порівняй `hint` + `give_up` з `game_start`. Якщо підказок більше, ніж
партій, — гравці часто застрягають.

**Телефон чи комп'ютер для конкретної гри.** **Events** → фільтр *game = sketch* → `game_start` → `device`.
Корисно перед змінами інтерфейсу: якщо в гру грають з телефона — спершу перевіряти мобільний вигляд.

**Соло проти компанії.** **Events** → `game_start` → `mode`. Для конкретної гри — додай фільтр *game*.

**Скільки людей зазвичай у кімнаті.** **Events** → фільтр *mode = room* → `game_start` → `players`.

**Ефект оновлення.** Після помітної зміни (див. «Що нового») відкрий **Compare** або постав період «7 днів після»
і порівняй з «7 днів до»: Visitors, `game_start` потрібної гри.

**Хто зараз грає.** **Realtime** — активні відвідувачі, сторінки й події за останні хвилини.

## 6. Reports — складніші звіти (за бажанням)

Вкладка **Reports** (або **Reports** у верхньому меню) — звіти, які налаштовуються один раз і зберігаються:

- **Funnel** (воронка) — скільки людей пройшло кроки по черзі. Наприклад: сторінка `/` → сторінка `/fours/` →
  подія `game_start` → подія `game_finish`. Видно, на якому кроці відпадає найбільше.
- **Goals** (цілі) — стежити за одним числом, наприклад «скільки `game_finish` за тиждень».
- **Retention** — чи повертаються люди через день/тиждень.
- **Journey** — якими шляхами ходять по сайту (з головної — в які ігри, і куди далі).
- **Insights** / **Breakdown** — таблиця подій або сторінок з розрізом одразу за кількома ознаками (країна × пристрій тощо).

## 7. Що варто знати

- **Visitors — це браузери, а не люди.** Той самий друг з телефона й з комп'ютера — двоє відвідувачів; режим інкогніто — новий відвідувач.
- **Блокувальники реклами** інколи ріжуть статистику — справжніх відвідувачів трохи більше, ніж показує Umami.
- **«Перехрестя»** завжди пише `mode = room` — окремого соло-режиму в нього немає.
- `players` береться в момент події: у `game_start` — скільки сіли грати; хтось міг доєднатись пізніше.
- Число «Зараз на сайті» на головній рахує сам сайт, а не Umami, тож воно може трохи відрізнятись від **Realtime**.
- Нова подія з'являється в Umami лише після того, як її хтось реально надіслав на справжньому сайті.

Технічно: скрипт підключення й `window.Track` — `public/shared/analytics.js`; події ігор — `public/shared/room-client.js`
(і `public/crossroads/app.js`), відгуки — `public/shared/feedback.js`.
